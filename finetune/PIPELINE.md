# Fine-tuning пайплайн для голосового бота «Дмитрий»

Подготовка данных из логов колл-центра и дообучение open-модели (Qwen2.5) под
поведение оператора. LLM работает **перед TTS**, поэтому формат речи (ударения,
числа прописью) сохраняется.

## Цель и решения

| Вопрос | Решение | Почему |
|---|---|---|
| Что улучшаем | Поведение: стиль, следование плану, отработка возражений, формат под TTS | FT учит поведению, не фактам |
| Факты (ставки/сроки) | Остаются в system-промпте / RAG, НЕ в весах | Меняются; зашитые в веса → модель врёт устаревшее |
| Метод | LoRA (адаптер ~десятки МБ) | Дёшево, swappable, база не портится |
| Ученик | **Qwen2.5-14B-Instruct** | Компромисс на 40 ГБ VRAM: QLoRA-трейн + fp16-прод с низкой latency |
| Учитель (для синтетики) | Claude/GPT через API | Должен быть сильнее ученика, иначе дистилляция бессмысленна |
| Объём данных | 4481 записей → **2810 уникальных** диалогов (1622 дубля-ретрая выкинуты) | Средний пул → синтетика для v1 не нужна |

## Принцип очистки данных

- **user-турны = сырой вход.** В проде модель получает кривой ASR
  («в моей соц уже все», «тадара») — поэтому в датасете user-турны **не чистим**.
  Иначе train/serve mismatch и деградация в бою.
- **assistant-турны = цель генерации.** Чистим артефакты: убираем `*перебили*`,
  чиним разрывы слов («ра йон»→«район»). TTS-ударения (`одОбрить`) **сохраняем**.
- **Отбор полезности:** недозвоны и диалоги без реального ответа клиента
  отсеиваются (мин. 4 сообщения и ≥2 содержательных реплики клиента).
- **Дедуп (по умолчанию вкл):** точные дубли диалогов (ретраи вебхука)
  выкидываются ДО train/val split — иначе один звонок давит на обучение и
  протекает между train и val. Отключить: `--no-dedup`.

## Скрипты

| Файл | Назначение |
|---|---|
| `extract_finetune.py` | Лог → чистый JSONL `{"messages":[...], "meta":{...}}` для FT |
| `gen_strategy_a.py` | Дистилляция: учитель переписывает ответы Дмитрия на реальных скелетах |
| `train_lora_qwen.py` | LoRA-обучение Qwen2.5-14B (Unsloth, на GPU-боксе) |
| `a.py` | (существовавший) санитайзер PII — отдельная задача |

### Формат данных

Каждая строка JSONL:
```json
{"messages": [
  {"role": "system", "content": "<sellerRole + style + plan + facts + rules>"},
  {"role": "assistant", "content": "АлОм."},
  {"role": "user", "content": "алло"},
  ...
], "meta": {"status": "transfer", "lead_quality": 8, "client_facts": "..."}}
```
- `system` собран из `skillbase` лога. `meta` — исход звонка (метка, тренером игнорируется).
- Формат `messages` маппится в ChatML Qwen один-в-один.

## Команды

### 1. Извлечение из логов
```bash
# базовая очистка (без зависимостей)
python3 extract_finetune.py requests.log data.jsonl

# + склейка разорванных слов (нужна морфология) + train/val split
pip install pymorphy3 pymorphy3-dicts-ru   # лучше в venv (PEP 668)
python3 extract_finetune.py requests.log data.jsonl --clean --val-split 0.1
```
Флаги: `--clean` (склейка слов), `--normalize-stress` (опустить ударения — НЕ нужно
для LLM перед TTS), `--min-quality N`, `--only-transfer`, `--val-split`, `--seed`.

> На малом пуле (264) фильтры `--only-transfer --min-quality` могут срезать данные
> до ~120 — проверяй `kept` и не пережимай.

### 2. Генерация синтетики (стратегия A — реальные скелеты)
```bash
export ANTHROPIC_API_KEY=sk-ant-...
# СНАЧАЛА тест на 5 — прочитать глазами (факты! длина! ASR-вход на месте!)
python3 gen_strategy_a.py data.jsonl data.distilled.jsonl --limit 5
# ок -> полный прогон
python3 gen_strategy_a.py data.jsonl data.distilled.jsonl
```
- Сохраняет реальные user-турны (ASR-шум), переписывает только ответы Дмитрия.
- Учитель: `claude-sonnet-4-6` (дороже/качественнее — `claude-opus-4-8`).
- Стоимость: ~4000 вызовов ≈ **$30–60 Sonnet**. Снизить — prompt caching.

### 3. Обучение LoRA (на GPU-боксе, 40 ГБ VRAM)
```bash
pip install unsloth
pip install --no-deps trl peft accelerate bitsandbytes
python3 train_lora_qwen.py    # -> qwen-mif-lora/ (адаптер)
```
Гиперпараметры под малый датасет: rank 16, dropout 0.05, lr 1e-4, 3 epochs,
`train_on_responses_only` (учим только ответы Дмитрия), `load_best_model_at_end`
по `eval_loss`. Следи за `eval_loss`: растёт при падающем train → переобучение.

## Синтетические данные — грабли и рецепт

**Проблемы наивной синтетики:**
1. Рассинхрон входа — генератор пишет чисто, прод даёт кривой ASR. ← стратегия A
   решает: реальные user-турны.
2. Потолок дистилляции — учитель должен быть сильнее ученика (не 7B→7B).
3. Факт-галлюцинации — пинить факты из конфига.
4. Слишком сговорчивый клиент — редкие возражения покрываются плохо.

**Рецепт (bootstrap от реальных):**
- **A. Реальные скелеты** + переписанный ассистент — реализовано (`gen_strategy_a.py`).
- **B. Симуляция диалогов** (клиент-бот × Дмитрий-бот) для покрытия редких сценариев + ASR-шум на синтетический вход — *не реализовано, следующий шаг*.
- + judge-фильтр, факты из конфига.

## План развития

1. **v1 сейчас:** 264 реальных + дистилляция A → обучить Qwen2.5-14B LoRA, найти слабые места.
2. **Копить данные:** лог растёт с каждым звонком.
3. **v2 (800–1500 звонков):** осмыслен фильтр `--only-transfer --min-quality 7`,
   rank 16→ можно выше, system-промпт можно срезать.
4. **Стратегия B** для покрытия редких возражений.

## Ожидания от v1

Заметно подтянет стиль/тон/формат-под-TTS, следование плану. Редкие сложные
возражения — скорее нет (мало примеров). FT дополняет system-промпт, не заменяет
его (на малом пуле промпт НЕ укорачивать).
